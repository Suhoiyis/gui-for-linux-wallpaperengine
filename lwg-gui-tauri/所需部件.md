## ❓版本号 0.1.0 来自两个地方（需要保持同步）：

1. Rust 后端（src-tauri/Cargo.toml）
   [package]
   version = "0.1.0"
   → lib.rs 中通过 env!("CARGO_PKG_VERSION") 读取
2. Tauri 配置（src-tauri/tauri.conf.json）
   {
   "version": "0.1.0"
   }
   → 用于应用打包时的版本标识

两者必须一致。如果要更新版本号，需要同时修改这两个文件。

目前 Tauri 版本的默认版本号如下：

当前版本配置

| 文件                      | 版本号 | 说明            |

| Tauri 框架版本

总结: 你的应用目前使用的是 0.1.0 作为默认版本号，这是一个典型的早期开发版本标识。Tauri 框架本身使用的是 v2 系列（最新稳定版）。

#### 📂 Tauri 版 JSON 文件分离方案 (当前实现)

##### 1. 用户配置 (User Preferences)

位置: `~/.config/linux-wallpaperengine-gui/config.json`

存储用户的手动设置，不包含运行时状态。

```json
{
  "fps": 30,
  "volume": 50,
  "scaling": "default",
  "clamping": "clamp",
  "muteAudio": false,
  "noFullscreenPause": false,
  "disableMouse": false,
  "noAutomute": false,
  "noAudioProcessing": false,
  "disableParallax": false,
  "disableParticles": false,
  "screenshotDelay": 20,
  "screenshotRes": "3840x2160",
  "preferXvfb": true,
  "cycleEnabled": false,
  "cycleInterval": 15,
  "cycleOrder": "random",
  "workshopPath": "/path/to/workshop",
  "assetsPath": null,
  "waylandOnlyActive": false,
  "waylandIgnoreAppids": "",
  "compactMode": false,
  "wallpaperProperties": {},
  "wallpaperNicknames": {},
  "autoRestore": false
}
```

##### 2. 运行时状态 (Runtime State)

位置: `~/.local/state/linux-wallpaperengine-gui/state.json`

直接映射：屏幕名 → 壁纸状态。可以安全删除（删除后应用将以空状态启动）。

```json
{
  "HDMI-1": {
    "wallpaperId": "2874425843",
    "isPlaying": true
  },
  "eDP-1": {
    "wallpaperId": "2810924556",
    "isPlaying": false
  }
}
```

**字段说明**:

- `wallpaperId`: 壁纸 ID
- `isPlaying`: 是否正在播放
  - `true`: 该屏幕正在播放此壁纸
  - `false`: 该屏幕已停止播放，但保留历史记录

**行为**:

- 播放壁纸 → 设置 `isPlaying: true`
- 停止壁纸 → 设置 `isPlaying: false`（保留条目，不删除）
- 应用重启后可恢复 `isPlaying: true` 的屏幕（需启用 `autoRestore`）

**autoRestore 配置**:

- `autoRestore: true` → 应用启动时自动恢复上次播放的壁纸
- `autoRestore: false` → 应用启动时不恢复壁纸（默认）

##### 3. 播放历史 (Playback History)

位置: `~/.cache/linux-wallpaperengine-gui/history.json`

遵循 XDG 缓存规范，存储最近播放的壁纸记录（最多 30 条）。

```json
[
  {
    "id": "2874425843",
    "title": "壁纸标题",
    "preview": "/path/to/preview.jpg",
    "timestamp": "2026-03-08T17:30:00"
  }
]
```

##### 4. 截图历史 (Screenshot History)

位置: `~/.cache/linux-wallpaperengine-gui/screenshot_history.json`

遵循 XDG 缓存规范，存储最近的截图记录（最多 10 条）。

```json
[
  {
    "timestamp": 1741785600,
    "wpId": "2874425843",
    "outputPath": "/home/user/Pictures/wallpaperengine/2026-03-12_20:30:00_3840x2160_2874425843.png",
    "duration": 10.5,
    "maxCpu": 45.2,
    "maxMem": 512.8
  }
]
```

**字段说明**:

- `timestamp`: 截图完成时的 Unix 时间戳（秒）
- `wpId`: 壁纸 ID
- `outputPath`: 截图文件保存路径
- `duration`: 截图过程耗时（秒）
- `maxCpu`: 截图过程中最大 CPU 使用率（%）
- `maxMem`: 截图过程中最大内存使用（MB）

**行为**:

- 每次截图后自动添加记录到队列头部
- 超过 10 条时自动移除最旧的记录
- 清空截图历史时同步清空文件
- 文件损坏时自动重置为空历史

**管理器**: `ScreenshotHistoryManager`（独立于 `PerformanceMonitor`，使用 `tokio::sync::Mutex`）

#### 🎯 关键设计要点

1. **破坏性变更**: 不再兼容 Python 版本的 `config.json`。
2. **状态持久化**: `state.json` 存储所有屏幕的壁纸状态，包括已停止的壁纸（`isPlaying: false`）。
3. **可丢弃性**: `state.json`、`history.json` 和 `screenshot_history.json` 都可以随时删除，系统会自动重新生成。
4. **符合 XDG 规范**: 严格区分配置 (Config)、状态 (State) 和缓存 (Cache) 目录。
5. **并发安全**: `ScreenshotHistoryManager` 使用 `tokio::sync::Mutex`，独立于 `PerformanceMonitor`，避免阻塞后台性能监控线程。

6. **状态持久化**: `state.json` 存储所有屏幕的壁纸状态，包括已停止的壁纸（`isPlaying: false`）。
7. **可丢弃性**: `state.json` 和 `history.json` 都可以随时删除，系统会自动重新生成。
8. **符合 XDG 规范**: 严格区分配置 (Config)、状态 (State) 和缓存 (Cache) 目录。

#### 🔄 操作与 state.json 更新

| 操作       | state.json 更新                                |
| ---------- | ---------------------------------------------- |
| 播放壁纸   | 设置该屏幕 `isPlaying: true`                   |
| 停止单屏幕 | 设置该屏幕 `isPlaying: false`                  |
| 停止所有   | 设置所有屏幕 `isPlaying: false`                |
| 随机壁纸   | 调用播放壁纸逻辑                               |
| 应用重启   | 读取 state.json，恢复 `isPlaying: true` 的屏幕 |

## ❗应用重启功能注意事项

### 已实现功能

- `quit_app` 命令：停止壁纸后退出应用
- `restart_app` 命令：停止壁纸后重启应用
- 退出确认对话框：防止误操作
- 托盘菜单退出：同样会停止壁纸

### 已知问题：开发模式下重启失败

**现象**：在 `npm run tauri dev` 开发模式下点击重启，新窗口显示白屏或 "Could not connect to localhost: Connection refused"。

**原因**：

1. 开发模式下，Tauri webview 连接到 Vite 开发服务器 (`http://localhost:1420`)
2. 当前重启逻辑只重启 Tauri 后端二进制文件
3. 新进程尝试连接 Vite 服务器失败（可能连接断开或环境变量未正确传递）

**尝试过的解决方案**：

1. 设置 `process_group(0)` 创建新进程组
2. 使用 `Stdio::null()` 分离终端
3. 设置 `TAURI_DEV_SERVER_URL` 环境变量

**当前状态**：开发模式下重启功能不可用，生产模式（AppImage、deb 等）正常工作。

**建议**：

- 开发测试时手动重启（Ctrl+C 后重新运行）
- 或者后续研究：在开发模式下通过 shell 命令启动 `npm run tauri dev` 而非直接运行二进制文件
